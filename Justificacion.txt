En este caso lo que pasa es debido a la concurrencia y al controlador de procesos, el cual le puede asignar un
mayor tiempo a un hilo que a otro, en el caso de que se lo de al getter este repetiría varias veces el mismo valor
de la variable, debido a que el setter no podría acceder a la variable, en cambio si le diera más tiempo al setter
lo que pasaría es que el hilo setter podría modificar varias veces la variable y que el getter no imprimiera esos valores
porque no podría acceder para imprimirlo.


¿Cómo solucionarlo?
Debemos de proteger la región crítica que es la que modifica la variable, en este caso lo mejor sería
modificar el setter y el getter en la variable compartida sincronizandolas y también poner un sleep en el método
run de la hebra set.

//Clase VariableCompartida Corregida
public class VariableCompartida {
    private int variableV=0;

    public synchronized int getVariableV() {
        return variableV;
    }

    public synchronized void setVariableV(int variableV) {
        this.variableV = variableV;
    }
}
